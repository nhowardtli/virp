Authentication and authorization only. No Cisco device was touched; the

## 1. What was built

| | |
|---|---|
| Host | CT 215 `virp-tacacs`, Debian 12.12, unprivileged, 1 core / 512 M / 4 G |
| Storage | rootfs on **`local`** (dir), *not* `local-lvm` |
| Software | tac_plus-ng `fd4818b71485f5746a522242027133c26092f9f6`, PCRE2, OpenSSL 3.0.20, built from source |
| Service | `virp-tacacs-authz.service`, enabled, `Type=exec`, `Restart=always` |
| Identities | `virp-ro` (priv 1), `virp-rw` (priv 15). **No human accounts** (§9.1). |
| Secrets | `/etc/tacacs/secrets.conf`, 0600 root:root, generated on the box, never printed |
| Decision log | `/var/log/tacacs/authz.log` — permits **and** denials |

**Storage note.** The rootfs is deliberately not on `local-lvm`. VM 313
lives in that thin pool, and a pool that fills takes every volume on it
read-only at once. Keeping the authorization server out of it means a
storage failure on the gate's pool cannot take authorization with it —
the same separation argument as §9.4, applied to disk.

### Policy files

| File | Mode | Generated? | Purpose |
|---|---|---|---|
| `tac_plus-ng.cfg` | 0600 | no | profiles, logging, include order |
| `guard.conf` | 0644 | **yes** | hard denials, both profiles, evaluated first |
| `green.conf` | 0644 | **yes** | the 38 GREEN commands, `virp-ro` |
| `approved.conf` | 0644 | no | **the seam.** Ships empty = deny all. |
| `secrets.conf` | 0600 | on install | device keys + account passwords |

`green.conf` and `guard.conf` are generated by
`deploy/tacacs/gen-green-conf.py` **from `src/drivers/driver_cisco.c`**,
not hand-copied. The generator parses the gate table, refuses to emit if
a YELLOW or RED row is reachable by a string that also matches a GREEN
row, and round-trips every command through the repo's own
`ios_canonical()`. All 38 GREEN entries were already canonical. If the
driver table changes, regenerate; an edit to the installed file makes the
gate and the authorization server disagree about what GREEN means, and
nothing would detect that.

### Match semantics

`virp-ro` uses the **driver's own longest-prefix, token-boundary**
semantics (`--prefix`), so `show interfaces GigabitEthernet0/0` is
permitted by the `show interfaces` row, exactly as `cisco_gate_tier()`
would classify it, while `show bootleg` is still denied because the tail
must begin at a token boundary.

`virp-rw` grants are **exact**, one rule per approved command.

## 2. FOR THE approved.conf WRITER — read this before writing a grant

Three properties of this server that a bounded-TTL writer must build
around. Each was measured here, not assumed.

### 2.1 Effective revocation = written TTL + up to 8 s

A reload is not instantaneous, and the delay applies to **revocations as
much as grants**.

`tacacs-reload` checks the config and sends `SIGHUP` to the spawnd
master. spawnd only *processes* pending signals when the wall-clock
second is a multiple of 8 — `mavis/spawnd_main.c:76`:

```c
if (io_now.tv_sec & 7) { DebugOut(DEBUG_PROC); return; }
spawnd_process_signals();
```

`periodics()` is scheduled every 1 s (`spawnd_main.c:585`), so the SIGHUP
sits pending until the next multiple-of-8 second. Measured over 12
randomized-arrival trials: **min 733 ms, median 5609 ms, max 7681 ms** —
uniform across an 8-second window, as the source predicts.

**A grant remains in force for up to 8 seconds after its TTL expires and
`tacacs-reload` returns.** A writer that treats `tacacs-reload` returning
as "the grant is gone" is wrong by up to 8 seconds. Either subtract 8 s
from the intended TTL, or poll the policy until it reflects the change
before declaring the window closed.

This is not tunable from the config; it is a compile-time constant in
spawnd. Patching `& 7` is the only way to shorten it, and that forks the
upstream binary.

### 2.2 Grants MUST use `\A` and `\z`, never `^` and `$`

tac_plus-ng compiles every PCRE2 pattern with `PCRE2_MULTILINE`
(`tac_plus-ng/config.c:5136`). Under `MULTILINE`, `^` and `$` match at
**embedded newlines**. Measured against this server before the fix: a
forged

```
cmd=show  cmd-arg=version\nconfigure terminal  cmd-arg=<cr>
```

reassembles to `show version\nconfigure terminal <cr>`, whose *first
line* matches `/^show version$/` — and the command was **PERMITTED**.

`\A` and `\z` anchor to the absolute start and end of the subject and are
unaffected by `MULTILINE`. All generated rules now use them, and every
rule the writer emits must too. **A grant written with `^` and `$` is a
bypass, not a grant.** Correct shape:

```
if (cmd =~ /\Aconfigure terminal(?: <cr>)?\z/) { permit }
```

`guard.conf` also denies control bytes outright, so this specific vector
is now refused twice. Both layers are deliberate.

### 2.3 Truncate the file; never delete it

tac_plus-ng treats a non-matching `include` as `GLOB_NOMATCH` → parse
error (`mavis/mavis_parse.c:764`). Deleting `approved.conf` therefore
fails the whole config: `tacacs-reload` refuses to signal and the running
policy stays as it was, and a *restart* would refuse to start at all.

Emptying the file revokes every grant. Deleting it eventually takes the
server down. Those are very different outcomes and only one is intended.

### Two more things that help rather than hurt

- **The `<cr>` terminator.** IOS sends `cmd=show`, `cmd-arg=version`,
  `cmd-arg=<cr>`; tac_plus-ng joins them with single spaces
  (`author.c:eval_args`) into `show version <cr>`. Every rule must
  tolerate the optional trailing ` <cr>`. The corpus form in
  `tests/fixtures/ios_respelling_corpus.json` already carries it, so a
  writer using `ios_canonical()` plus `(?: <cr>)?` is consistent with the
  accounting side for free.
- **`guard.conf` is a floor the writer cannot grant past.** It is
  included ahead of `approved.conf` in the `virp-rw` profile, so an
  approved `configure terminal` can never become
  `configure terminal | redirect flash:x`. The writer does not have to
  re-implement separator checking, and a bug in the writer cannot open
  that hole.

## 3. Fail-closed behaviour

| Path | Guard | Verified |
|---|---|---|
| `systemctl start` / `restart` | `ExecStartPre=tac_plus-ng -P` | bad config → service does not start |
| `systemctl reload` / `tacacs-reload` | wrapper re-checks, refuses to signal | bad config → **running policy untouched**, exit 1 |
| Unparseable policy | no partial load | server down = every command denied on every device |

Measured: a malformed `approved.conf` left the daemon serving the
last-good policy at the same pid, and `systemctl restart` refused to
start. `tacacs-reload` reported the parse error and `running policy is
UNCHANGED`.

### The cells the `--prefix` switch was made for

| Command | Result |
|---|---|
| `show interfaces GigabitEthernet0/0` | **PERMIT** |
| `show version \| include x` | **PERMIT** |
| `show version \| redirect flash:x` | **DENY** |
| `show version ; reload` | **DENY** |

Pipe modifiers, exhaustively: `include`, `exclude`, `begin`, `section`,
`count` permit; `redirect`, `tee`, `append`, `format`, a bare `|`, and a
second pipe (`| include x | redirect flash:y`) all deny. Token boundary
holds: `show boot` permits, `show bootleg` denies. The guard applies to
`virp-rw` too: with `configure terminal` granted,
`configure terminal ; reload` and `configure terminal | redirect flash:x`
are both denied.

**40/40 checks pass.**

### Adversarial, forged packets

Bypassing IOS-style tokenizing and crafting AUTHOR args directly: doubled
space inside `cmd=`, trailing `;reload`, pipe redirect, `$(...)`,
newline injection, case variation, leading space, and `<cr>` in the
middle — **all denied**. Permitted: the baseline, the whole command in a
single `cmd=`, and `show version detail` (correct under prefix
semantics).

## 5. Three defects found and fixed during the build

1. **Authorization bypass via `PCRE2_MULTILINE`.** §2.2 above. A newline
   in a forged `cmd-arg` was permitted. Fixed with `\A`/`\z` plus a
   control-byte denial in `guard.conf`.

2. **The service died silently on the second reload.** With
   `background = yes`, spawnd re-daemonizes on each SIGHUP `execve`, so
   the master took a **new pid** every reload. systemd went on tracking
   the pid from the pidfile it read at start, saw it vanish, and logged
   `Deactivated successfully` — a *clean* exit, so `Restart=on-failure`
   never fired and the authorization server was simply gone. Fixed:
   `background = no`, `Type=exec`, no `PIDFile`, `Restart=always`, so
   `execve` preserves the pid. Survived 12+ consecutive reloads with
   `MainPID` stable.

3. **All five legal pipe modifiers were denied.** The guard's
   `\|\s*(?!(?:include|…)\b)` backtracked `\s*` to zero width and
   evaluated the lookahead at the *space*, where `include` does not
   match, so the negative lookahead succeeded and denied everything.
   Fixed by making it possessive — `\s*+` — so the lookahead lands on the
   modifier. Caught only because the test asserted the permits, not just
   the denials.

Also: `password pap = login` is required per user. PAP is a separate
credential slot in tac_plus-ng and authentication returns FAIL without
it, even with a correct login password.

## 6. Limits — what this does not do

- **Decisions are not chained.** `/var/log/tacacs/authz.log` is a plain
  local file, unsigned, rotatable, on the box being trusted. It is the
  only record of a refusal until `tacacs_authorization/1` (§8a) is wired,
  and it satisfies none of that schema's fields — no `policy_sha256`, no
  `producer_key_id`, no `raw_body_sha256`. It is a lead, not evidence, in
  exactly the sense §9.4 uses for the router's local buffer.
- **`policy_sha256` is not emitted per decision.** §8a calls it "the
  field that makes the record auditable". tac_plus-ng cannot compute it;
  binding a decision to the exact policy bytes it was judged against
  needs the chaining work, not a config change.
- **One shared key for all 35 routers**, matching the single credential
  the lab already shares across R1–R35. Compromise of one router is
  compromise of the fabric's TACACS+ key. Recorded, not fixed here.
- **No 2960 has been configured**, and whether it gets authorization at
  all is an open decision — see §3 of the runbook, particularly that some
  12.2 images have no `aaa authorization commands 1`, which would leave
  `show` commands unauthorized on that device.
- **Nothing has been applied to any Cisco device.** The runbook is
  derived from §7.3, which was measured on a 7206VXR running IOS
  15.2(4)M7 — not on the 2960 and not on IOS-XE.
