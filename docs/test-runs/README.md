# Test-run summaries — what is and is not evidence

Files here are **hand-written summaries** for humans. They are secondary
evidence: useful narrative, but a person transcribed the hashes, and one
of them proved the point — `all-tests-2026-08-18.md` tested `f200e621`
while the release archive of the day was cut from `cd351af6`, so the
committed evidence proved a nearby tree, not the shipped one.

The authoritative, machine-written record is the **test attestation**:

- every CI push uploads `test-attestation-<sha>` (workflow artifact) —
  the full battery pinned to the exact commit it ran against, with real
  exit codes, generated by `scripts/gen-test-attestation.sh`;
- every release ships `virp-<tag>.test-attestation.json`, hash-bound into
  the signed `MANIFEST.sha256` — and the bundling script refuses an
  attestation for any commit other than the one being archived.

Rules for adding a summary here:

1. Name the **exact commit** (full hash) the run tested, and say so if it
   was not a main head.
2. Prefer linking/attaching the machine attestation for the same commit;
   a summary without one is narrative, not proof.
3. Never present a run against one tree as evidence for another — if the
   tested commit and the shipped commit differ, that difference is the
   headline, not a footnote.
