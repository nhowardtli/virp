# unit-manifest.txt — tracked unit file → the path it is installed to.
#
# This is the map scripts/check-unit-drift.sh walks to compare what is
# TRACKED against what is RUNNING. It exists because `make
# check-deploy-unit` used to grep only the repo copy, so it passed
# green for eight days while /etc/systemd/system/virp-onode.service
# said the opposite of deploy/virp-onode.service (VIRP_WAZUH_INSECURE=1
# inline in the installed unit, discovered 2026-08-09). A check that
# reads only the file in git cannot see the file that boots the daemon.
#
# Format, one pair per line:
#   <tracked-path> <installed-path>
#
# Rules the checker applies:
#   - installed file absent           → skipped, reported, not a failure
#     (nodes have different roles; virp-node2 runs no config-backup)
#   - installed file present          → must be BYTE-IDENTICAL to tracked,
#     comments included. A comment that misdescribes the policy is how
#     this drift stayed invisible; "it's only a comment" is exactly the
#     argument that would have hidden it.
#   - installed virp-* file NOT named here → failure, "untracked"
#     (this is what surfaces a unit that exists only on the host)
#
# Host-specific settings do NOT belong here and do NOT belong as edits
# to a tracked unit. They belong in a DROP-IN, which is itself tracked
# and listed below. See deploy/unit-drift-allowlist.txt.

# ── netclaw egress lockdown ───────────────────────────────────────────
# Tracked 2026-08-09. Both files existed only on the host until then:
# the unit was enabled, systemd had never run it (no journal entries,
# ActiveState=inactive), and the nft table was nonetheless loaded in the
# kernel because someone applied it by hand with `nft -f`. The control
# was in force and simultaneously unowned, unreviewed, and would not
# have survived a rebuild.
#
# The ruleset is NOT a systemd unit and does not live under
# /etc/systemd/system — it is listed here anyway because the thing that
# needs to not drift is the RULE, not the unit that loads it. A unit
# that faithfully installs an edited ruleset is not a working control.
deploy/virp-netclaw-egress.service /etc/systemd/system/virp-netclaw-egress.service
deploy/nftables-virp-netclaw-egress.nft /etc/nftables-virp-netclaw-egress.nft

# ── virp-onode-home (10.0.0.13), tracked 2026-09-03 ───────────────────
# The home node runs the SAME base unit as the colo node — deploy/
# virp-onode.service above — and expresses its three differences in a
# drop-in, per this file's own policy. There is no second tracked unit
# for the same installed path, so nothing here is ambiguous about which
# source a host is compared against.
#
# The device TEMPLATES are deliberately absent from this manifest, both
# of them. deploy/devices.template.json and
# deploy/devices.home.template.json install to the same path,
# /etc/virp/devices.template.json, on their respective nodes — the exact
# one-tracked-file-per-installed-path collision the drop-in above
# avoids, and one a drop-in cannot solve because a device template is
# data, not a unit with an override mechanism.
#
# Listing either one alone would make this file assert that every node
# runs that node's fleet, which is false and would report the other node
# as drifted forever. Templates are compared instead by
# tools/state/drift-check.sh, which reads the node's OWN state document
# and therefore knows which template that node was rendered from. That
# is the right place for a per-node comparison; this file is for
# comparisons that are the same everywhere.
deploy/virp-onode-home.dropin.conf /etc/systemd/system/virp-onode.service.d/40-home.conf

# ── deployed-state reporter ───────────────────────────────────────────
# Tracked 2026-09-02, installed nowhere yet. Listed from the start
# rather than when it is first deployed, because "the unit exists only
# on the host" is precisely the condition that hid the netclaw egress
# ruleset above, and a manifest that only learns about a unit after
# someone remembers to add it is the same check that passed green for
# eight days.
deploy/virp-deployed-state.service /etc/systemd/system/virp-deployed-state.service
deploy/virp-deployed-state.timer /etc/systemd/system/virp-deployed-state.timer

# ── optional integrations ─────────────────────────────────────────────
# Not installed on virp-lab. Listed so that a node which DOES install it
# gets the same comparison as everything else — an optional component is
# still a component, and "optional" is not a reason to stop diffing it.
integrations/prometheus/virp-prometheus-exporter.service /etc/systemd/system/virp-prometheus-exporter.service

# ── O-Node drop-ins ───────────────────────────────────────────────────
# The installed NAMES carry a numeric ordering prefix that the tracked
# filenames do not; the mapping is only meaningful here, which is part
# of why an automated comparison needed a manifest rather than a glob.

deploy/virp-onode-evidence.dropin.conf /etc/systemd/system/virp-onode.service.d/51-evidence.conf

deploy/virp-onode-wazuh-lab.dropin.conf /etc/systemd/system/virp-onode.service.d/60-wazuh-lab.conf
