# VIRP demo

A deterministic, self-contained demonstration of nine VIRP security behaviors.
No router, hypervisor, credentials, or network access required.

Recommended path (Debian/Ubuntu):

```bash
git clone https://github.com/nhowardtli/virp
cd virp
sudo apt install -y build-essential libssl-dev libsodium-dev \
     libsqlite3-dev libssh2-1-dev libcurl4-openssl-dev libjson-c-dev
./demo/run.sh
```

A first run, including the dependency install and compile, takes about two
minutes. The demo needs no network access and no credentials.

## Alternative: containerized run

On modern Docker the compose plugin is invoked as `docker compose` (with a
space), but not all apt-packaged Docker builds ship the plugin:

```bash
docker compose -f demo/docker-compose.yml run --rm demo
```

If `docker compose` errors ("unknown command", "unknown shorthand flag"), use
the native path above — it is the reliable one.

## What it demonstrates

| # | Behavior | Mechanism exercised |
|---|---|---|
| 1 | A GREEN operation executes | tier gate classification |
| 2 | Its record verifies | HMAC-SHA256 observation authentication |
| 3 | Modifying the record causes verification failure | authentication tag over the record material |
| 4 | A RED operation is blocked | deny-by-default gate, proposal filed |
| 5 | An Ed25519 approval is created | approver key held outside the collector |
| 6 | The exact approved operation executes | approval bound to command hash and device |
| 7 | Reusing the approval fails | single-use consumption, persisted |
| 8 | An unknown operation fails closed | UNCLASSIFIED is blocked, not passed |
| 9 | The evidence chain verifies | keyed hash-linked chain, each entry commits to the previous |

On completion the harness prints a pass count and writes an evidence bundle:

```
VIRP DEMO PASSED
9/9 security behaviors observed
Evidence bundle: ./demo/output/session-<timestamp>
```

The bundle contains the per-step outputs, the daemon log, the demo device
configuration, the chain database, and a `SUMMARY.txt` recording the git commit
the run was produced from. Replay the chain at any time:

```bash
./build/virp-tool chain tail --db demo/output/session-<timestamp>/run/chain.db
```

## The target is simulated

`demo-r1` uses the built-in mock driver (`src/drivers/driver_mock.c`), which
returns canned, realistic-looking output deterministically. **No real device is
contacted.** The demo shows protocol behavior: what the gate classified, what
executed or was refused, what was authenticated, and what the verifier accepts
or rejects. It does not show, and VIRP does not establish, that any device
reported truthfully.

Keys generated by the demo are disposable and live only under the session
output directory. Do not reuse them for anything.

## What this demo does not show

- Security against a compromised collector. Every symmetric key holder must be
  treated as trusted; a collector that holds the key can fabricate records and
  rewrite the chain. External anchoring is designed, not done.
- Behavior against real vendor hardware. See the compatibility matrix on the
  specification page and the live transcript in `docs/LIVE-PROOF-2026-07-23.md`.
- Production readiness. VIRP is a research prototype and requires independent
  evaluation before production use.

The full statement of what has and has not been established is on the project's
security page: https://thirdlevel.ai/virp/security.html
